## TSword PS5 0.4.16-ut1

**0.4.15 got furthest yet:** past the title, through a loading screen, to the "Tears of the Kingdom" text, and frames ran at normal speed (about 30–50 ms) after a first-time texture load. Then both runs crashed **inside the game's own memory allocator** with a garbage pointer (`0x00ffff0000000000` in one, `0x8` in the other). That means the game's heap was corrupted.

**Why:** on the console TSword gave the GPU **copies** of the game's memory pools and copied GPU results back into game memory. Without the write watch (off since 0.4.5), the copy-back can't tell the game's newer bytes from the GPU's, so it put stale bytes over game memory, including the heap. UltraTears' own notes describe this failure from the Steam Deck.

- **Game memory is imported for the GPU (`TOTK_POOL_IMPORT=1`), as WSword does on this driver:** no copies and no copy-back, so nothing overwrites the game's data. It also saves about 1 GiB of memory.

**0.4.15's shader pack fix worked:** no more freezes at the title text. The 21-second first frame of the opening was the BC7 texture cache being read from USB for the first time. It's slow, but it finishes; speed comes later.

**No new PS5 export is needed.** Replace the title folder's files only.
