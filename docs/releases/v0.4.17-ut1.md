## TSword PS5 0.4.17-ut1

**0.4.16 crashed in the same game function as 0.4.15** (`f_1800082e00`, inside the game's memory allocator, about 2 s after the opening's first load). Importing game memory instead of copying it changed nothing, so the pool copies weren't the cause.

**Why:** safe mode (0.4.7) had turned off UltraTears' **virtual cores** (`TOTK_FREE_CORES=1`). The Switch has three cores, and the game's allocator keeps data for each core, chosen by the core a thread runs on. The virtual cores give the game exactly three cores, with one thread on each at a time. Without them, dozens of game threads ran at once under the same core numbers and corrupted that per-core heap data. Every crash since 0.4.7 has been in the allocator, or in thread creation.

- **Virtual cores are on again.** Asynchronous preemption stays off, so threads hand a core over at their next system call.
- Game memory stays imported for the GPU (0.4.16): no copies, about 1 GiB less memory.

**No new PS5 export is needed.** Replace the title folder's files only.
