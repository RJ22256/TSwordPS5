## TSword PS5 0.5.3-ut1

**The game's cores get physical cores of their own** (WSword PS5's CPU placement).

### Why
The game runs on three cores, as on the Switch. Until now, where the console ran each thread was left to its scheduler. A graphics recording thread or the shader compiler could land on the same physical core as the game's main thread, sharing it through hyper-threading. That slows down the thread whose speed sets the frame rate. WSword PS5 fixed this by giving the game's cores physical cores of their own, and its frame rate went up.

### What changes
- Each of the game's three cores runs on a physical core of its own (both hardware threads).
- Everything else runs on the cores left: graphics translation and recording, presenting, audio, the shader compiler and the driver's own threads.
- The log says where at the start: `[cpu] ... the game's cores 0-2 on CPUs ...`.
- **Speed-ups = Safe** turns it off. So does adding `TOTK_PS5_PIN=0` to `ultratears.cfg`.

### Also worth knowing (from your last log)
On **Full**, TSword is still compiling every one of the game's shaders ahead of time, once, in the background. The last log had done about 19,000 of 43,000, taking about 3 minutes of CPU per 9,000.
- **While it runs:** shader stutter is likely and one CPU core is busy.
- **When it finishes:** all of them are in `data/shaders/compiled-ps5.bin` and the stutter from new shaders goes away.
- To get there sooner, leave the game running for a while on Full.

**No new export beyond 0.5.2's.** 0.5.3 uses the same game code as 0.5.2, so if you already exported for 0.5.2, just replace the title folder's files.
