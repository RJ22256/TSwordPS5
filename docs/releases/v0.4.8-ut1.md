## TSword PS5 0.4.8-ut1

**What 0.4.6's stall report showed.** No thread was stuck on another and every virtual core was free. The game's main thread was waiting for its first frame to come back from the replayer, and the replayer never submitted that frame. The first real frame is where every shader it draws with is compiled. On a PC UltraTears loads saved driver binaries; the console starts with none, and its saved binaries were only flushed, never synced, so a reset by the power button lost them. The compile-ahead thread was also compiling the whole shader pack at the same time. So the most likely explanation is that TSword was compiling shaders, not frozen, with nothing on screen or in the log to say so.

- **The log shows shader progress**: every 2 s while compiling, a line with how many the driver has compiled this run, the time taken, the longest single one, and how many came from saved binaries. A compile over 2 s gets its own line, and the stall report adds the same line.
- **Compiled binaries are synced to the drive every 2 s** (`data/shaders/compiled.bin` beside the game data), so a power-button reset keeps them and the next start is faster.
- **The screen shows a slowly cycling colour** while the game's first frames are compiling, so a long first start no longer looks like a freeze.
- Safe mode from 0.4.7 stays, including no compile-ahead thread.

**First start: give it a few minutes.** If the colour is still cycling, it's working. Later starts reuse the saved binaries.

**No new PS5 export is needed.** Replace the title folder's files only.
