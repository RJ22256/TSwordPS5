## TSword PS5 0.4.13-ut1

**What 0.4.12's report showed:** game thread 0x1004 had been inside `nvnQueueSubmitCommands` for 10.7 s, holding the lock the main thread waited for. A batch of the game's drawing work went into the graphics layer and never came back. The GPU watchdog never fired, so no work reached the GPU and stayed there. That leaves the CPU side of the submit: the driver's own submit call, a lock, or a wait for GPU work that was never sent. The console froze at the first 3D scene, after "The Legend of Zelda" text.

- **The stall report says where inside a host call each thread is:** waiting for the GPU queue's lock, inside the driver's `vkQueueSubmit2`, waiting for a GPU submission to finish, or waiting for one of the replayer's locks, with how long.
- **It also counts GPU submissions:** made, given to the driver and finished, and whether one is still inside the driver's submit call.
- **GPU markers are on in safe mode** (`TOTK_VK_CHECKPOINTS=1`), so if the GPU itself stopped, the report names the commands it ran last.
